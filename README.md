# Overwatch — Android night-walk safety app

Overwatch watches where you are while you walk alone at night. If you stop moving for a
couple of minutes it asks whether you're okay. If you don't answer, it texts your
emergency contacts with your last location plus the nearest police station and hospital
numbers, and calls your emergency number.

Built with Kotlin + Jetpack Compose (Material 3), using the palette from
[colorhunt.co/palette/ffbe91ffddb0fffce1cfebff](https://colorhunt.co/palette/ffbe91ffddb0fffce1cfebff),
and an OpenStreetMap map view (osmdroid — no API key, no billing).

---

## What it does

**Sign in** first — email + password, or Continue with Google. Then Overwatch asks for
location, notification, motion and SMS/call permissions, and at least one emergency
contact before you can start.

**Start night watch** starts a foreground service that:

- streams high-accuracy GPS and keeps a fix;
- reads the accelerometer, gyroscope and step detector to know if you're moving;
- tracks the time since your last real movement (GPS jitter is ignored, so standing at a
  red light doesn't count as "moving" — but the bus stopping for 2 minutes might, which is
  why the pause button exists).

**Route tab** — set where tonight's walk starts and where it ends, either by pinning points
on the map or by using your current position as the start, then watch your own blue dot move
along the map in real time while the watch runs, with the distance left to your destination.

**Ask me if I haven't moved for 2 minutes** (configurable: 1/2/3/5 min) → the phone rings
an alarm, vibrates, shows a notification over the lock screen and opens a full-screen
check-in screen with **I'm safe**, **Pause checks for 30 min** and **I need help now**.

**Pause checks** (the "snooze") silences everything — no questions, no alerts — for
15/30/45/60 min. Trapped in traffic or waiting for someone? Pause instead of being nagged.

**No answer within 60 s** (configurable 30–90 s) → SOS:

1. Full-screen SOS screen with a big **Call 999 now** button and an 8-second auto-dial
   countdown.
2. An SMS to every emergency contact containing your last location as a Google Maps link,
   the nearest police stations (name, distance, phone) and the nearest hospitals.
3. The same numbers shown on screen, each with a one-tap call button, so whoever is with
   you — or the contact you phoned — can arrange help.

Contacts are managed in **Contacts** (add as many as you like; one is required). The
hotline and all timings live in **Settings**. **Activity** keeps a local log of every
watch, check-in, pause and SOS.

## Build and run

Requirements: **Android Studio** (Ladybug or newer), **JDK 17**, Android **SDK 34**.
`minSdk` is 26 (Android 8.0), so it runs on most phones in use today.

```bash
# open the folder in Android Studio, let it sync, then Run ▶
# or from a terminal with the SDK installed:
./gradlew assembleDebug
# APK: app/build/outputs/apk/debug/app-debug.apk
adb install app/build/outputs/apk/debug/app-debug.apk
```

The Gradle wrapper is included. `local.properties` is generated by Android Studio (or by
you) and is git-ignored; point `sdk.dir` at your SDK.

## Optional: enable "Continue with Google"

Google sign-in uses Android Credential Manager with an ID token, so it needs one free OAuth
client **created under your own Google account** — that step cannot be done by anyone else,
and it is the only reason the button is not live in a fresh build.

1. Go to [Google Cloud Console](https://console.cloud.google.com/) → create a project
   (free, no billing needed).
2. **APIs & Services → OAuth consent screen**: choose External, fill in the app name
   (`Overwatch`), your support email and developer email, then **Save**. While it stays in
   *Testing*, add your own Gmail address under **Test users**.
3. **Credentials → Create credentials → OAuth client ID → Android**, with:
   - package name: `com.traceme.app`
   - SHA-1: the debug signing certificate of this build
     (`cd android; keytool -list -v -keystore ~/.android/debug.keystore -alias androiddebugkey -storepass android -keypass android`).
4. **Create credentials → OAuth client ID → Web application** (any name, no redirect URIs
   needed). This is the one Credential Manager asks for.
5. Copy the **Web** client ID into `local.properties` (never commit this file):

   ```properties
   GOOGLE_WEB_CLIENT_ID=1234567890-abcdef.apps.googleusercontent.com
   ```

6. Rebuild. The Google button now opens the account picker.

Email/password registration works with no setup at all. Accounts are hashed with
PBKDF2-HMAC-SHA256 (120k iterations, per-account salt) and stored in app-private
SharedPreferences. **This is local-only auth** — there is no backend, so nothing syncs
between phones and a fresh install starts empty.

## Permissions and why

| Permission | Why |
| --- | --- |
| `ACCESS_FINE_LOCATION`, `ACCESS_COARSE_LOCATION` | The whole point: track where you are, and place you on the map. |
| `ACCESS_BACKGROUND_LOCATION` | Declared so location survives screen-off on aggressive OEM builds. Android asks for it separately ("Allow all the time") — optional. |
| `FOREGROUND_SERVICE`, `FOREGROUND_SERVICE_LOCATION` | The watch must keep running while you walk with the screen off; Android requires a visible notification for that. |
| `POST_NOTIFICATIONS` | The check-in must reach you on the lock screen. |
| `ACTIVITY_RECOGNITION` | Step detector — steps are the strongest "I'm moving" signal. |
| `SEND_SMS` | Sends the SOS text to your contacts. |
| `CALL_PHONE` | Places the call to the emergency number. Without it Overwatch only opens the dialer. |
| `VIBRATE`, `WAKE_LOCK`, `USE_FULL_SCREEN_INTENT` | Alarm behaviour and the full-screen check-in. |
| `INTERNET`, `ACCESS_NETWORK_STATE` | Map tiles, and the nearby police/hospital lookup. |

Grant at least location + SMS + notifications for the full flow. The Settings screen shows
each one's status and links to Android's app settings.

## Nearby police and hospitals

No API key, no backend: Overwatch queries the
[Overpass API](https://overpass-api.de/) for `amenity=police` (4 km) and `amenity=hospital`
(5 km) around your position, sorts by distance, and reads `phone` / `contact:phone` tags.
A second mirror is tried if the first fails. If a station has no phone number in
OpenStreetMap, Overwatch says "no number listed" instead of inventing one.

**The lookup no longer waits for the walking watch to have a fix.** Tapping *Find police &
hospitals* now asks the phone for a fresh high-accuracy fix itself (falling back to the last
known position), and if location is switched off it offers a **Turn on** button that opens
the system location settings.

## Honest limitations

- **Debug-signed only.** The APK is signed with the standard Android debug key; install it
  by sideloading. A Play release needs your own keystore and a release build.
- **Automatic calls are best-effort.** Android blocks background apps from starting
  activities/calls in some situations. Overwatch tries the call, and always leaves the
  dialer one tap away on the SOS screen. SMS/`ACTION_CALL` also need the permissions above
  and an active SIM with credit for SMS.
- **Battery optimisation can kill the watch.** On Xiaomi/Oppo/Vivo/Samsung builds, exclude
  Overwatch from battery optimisation and allow background activity, or the foreground
  service may be frozen. The service shows a persistent notification while it runs.
- **`SEND_SMS` / `CALL_PHONE` restrict Play Store publishing.** Google Play requires a
  declaration and review for these permissions; they are fine for personal/sideloaded use.
- **No backend, no tests.** Everything is on-device; there is no server, no test suite, and
  no cloud sync. Replace local auth with a real backend before any multi-user release.
- **The map is not a navigation engine.** It shows your position, a straight line between
  start and destination, and the distance left — it does not compute turn-by-turn street
  routing.
- **Nearby lookup needs internet** and OpenStreetMap data quality varies by city; phone
  numbers are often missing in South Asia. The emergency number always works.

## Project layout

```
app/src/main/java/com/traceme/app/
├── MainActivity.kt              single activity + bottom navigation
├── CheckInActivity.kt           full-screen "are you okay?" countdown
├── SosActivity.kt               SOS: call, text, nearby numbers
├── TraceMeApp.kt                notification channels + osmdroid cache setup
├── data/                        models, SharedPreferences repo, auth (PBKDF2 + Google)
├── location/
│   ├── TrackingService.kt       foreground service: GPS + sensors + escalation
│   └── SpotLocation.kt          one-off fix for Nearby Help and the map
├── emergency/
│   ├── EmergencyDispatcher.kt   builds the alert, sends SMS, dials
│   └── NearbyServices.kt        Overpass lookup, keyless
├── ui/                          theme, components, screens (incl. MapScreen)
└── util/                        notifications, permissions, alarm tone
```

The application id stays `com.traceme.app` (the source package was not renamed) so that
data, the launcher entry and any OAuth client already bound to the package keep working.

## Privacy

Location, contacts and the activity log stay in app-private storage on the phone. The only
network calls are map tiles and the Overpass lookup (coordinates only, no identifiers) and
Google sign-in if you choose it. No analytics, no ads, no server of ours.
